# blvcksyxx shell v1.11.1

v1.11.1 fixes the update from v1.1 that could leave the desktop without starting. It is a
small follow-up to [v1.11](v1.11.md); the shell itself is unchanged.

## What went wrong

An update keeps a QML file you changed and puts the new one next to it. On a computer that
came from v1.1, the installer compared the installed desktop files with v1.1 and saw a
difference in thirteen of them: `SoftShadow` had been renamed to `Shadow`. It treated that
rename as your edit, kept the old files and left the new ones as `FILE.rice-update`.

v1.11 also made `Player.qml` a singleton. The old `DynIsland.qml` and `ControlCenter.qml`
still created `Player { ... }` instances, so Quickshell failed to load the whole desktop:

```text
Type Bar unavailable
  Type DynIsland unavailable
    Composite Singleton Type Player is not creatable.
```

The same update could leave the lock screen without `shell.qml` or with an old `LockView.qml`
that still used `Player` and `SoftShadow`.

## What changed

- **The rename is not an edit.** The installer compares QML files with `SoftShadow` treated
  as `Shadow`, so the old files are replaced as they should be.
- **Kept files are migrated.** If you really changed a file, only the exact old patterns are
  rewritten, with a `FILE.before-v1.11.1` backup:
  - `SoftShadow` → `Shadow`;
  - desktop `Player { id: x; running: e }` → an `Instantiator` that calls `Player.hold()` /
    `Player.release()`, and `x.` → `Player.`;
  - lock screen `Player { ... }` → `LockPlayer { ... }`.
- **The desktop heals itself.** `rice-desktop` writes `~/.cache/rice/desktop.log`, notices
  when Quickshell quits while loading, takes the `.rice-update` files, migrates kept files,
  retries once, and shows a notification with the log path. Old files stay as
  `FILE.before-v1.11.1`. `rice-desktop status` only counts the real Quickshell process.
- **The lock screen heals itself.** `rice-lock` puts back a missing `shell.qml`,
  `LockView.qml`, `LockCtx.qml`, `LockCards.qml` or `LockPlayer.qml` from the repository,
  migrates kept files, and only then checks whether the shell can start.
- **Nothing is reset.** Settings, wallpapers and your own edits stay.

## Upgrade

From v1.11 (or a broken v1.11 install), in the repository:

```bash
git pull
./install.sh --update
```

From v1.1, the same commands go straight to v1.11.1. If the desktop is not running, open a
terminal with `SUPER + Enter` or switch to a TTY and run the commands there. The installer
restarts the desktop at the end and the self-healing takes over if an old file is still in
the way.

A fresh install is in the [README](https://github.com/blvcksyxx/blvcksyxx-shell#install-in-one-minute).

## Verifying the download

Release tags and `SHA256SUMS` are signed with the project's SSH signing key
(`SHA256:n/ILvwETafTMBy9wi162zxGxu6TL8M9i+GJKC3zOd0o`). Download `SHA256SUMS`,
`SHA256SUMS.sig` and `trusted-signers` next to the archive, then:

```bash
ssh-keygen -Y verify -f trusted-signers -I blvcksyxx-release \
  -n blvcksyxx-release -s SHA256SUMS.sig < SHA256SUMS
sha256sum -c SHA256SUMS
```

`install.sh --update` fetches the update, verifies that the exact commit is either a signed
release tag or a signed commit from the project key, and only then fast-forwards. More in
[SECURITY.md](https://github.com/blvcksyxx/blvcksyxx-shell/blob/main/SECURITY.md).
